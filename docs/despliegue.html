Despliegue

Cómo llevar cada módulo a una cuenta de OCI en un clic, qué revisar antes, y cómo no gastarse el crédito sin darse cuenta.

Cómo funciona el botón

Cada botón abre Oracle Cloud Resource Manager con un archivo ZIP preparado: la configuración de Terraform de ese módulo, junto a un schema.yaml que convierte las variables en un formulario con descripciones y valores por defecto, en vez de una lista de campos sueltos.

  1. Se abre la consola de OCI

    Hay que iniciar sesión en el tenancy donde se quiere desplegar. Resource Manager descarga el ZIP y crea un stack.

  2. Se completa el formulario

    Compartment, llave SSH, IP de acceso y los parámetros del laboratorio. Lo que no se toque queda con valores pensados para una demostración.

  3. Plan y luego Apply

    El plan muestra qué se va a crear antes de crearlo. Conviene mirarlo: es la misma revisión que se le pide a cualquier cambio de infraestructura.

  4. Al terminar, Destroy

    Desde el mismo stack. Es el equivalente a los scripts de borrado del repositorio.

Antes del primer despliegue

Límites de servicio

Es lo que más despliegues rompe en cuentas nuevas. Si un límite está en cero, la solicitud de aumento no es inmediata: puede tomar días. Conviene revisarlos con tiempo, en Governance & Administration → Limits, Quotas and Usage, para el shape de cómputo, el balanceador flexible y la base de datos administrada.

Nombres que cambian entre regiones

Tres cosas no se llaman igual en todas partes, y una configuración que las nombra mal falla de formas confusas:

QuéCómo verificarlo
Shapes de cómputo y de base de datos oci compute shape list · oci mysql shape list
Reglas de protección del WAF oci waf protection-capability list --key 941100
Nombres de métrica oci monitoring metric list --namespace oci_computeagent
El caso más traicionero: una alarma sobre una métrica que no existe se crea sin ningún error y nunca suena. En la consola se ve perfecta. Por eso el módulo 5 incluye un panel que distingue «tranquila» de «sin datos».

Destruir al terminar cada día no es opcional. Cada módulo trae su script; desde Resource Manager, la acción Destroy del stack hace lo mismo.

Ejecutarlo sin el botón

Todo funciona igual con Terraform desde un equipo. La única diferencia está en la autenticación: en Resource Manager la provee el servicio, y en local se usa el perfil de ~/.oci/config.

git clone https://github.com/jesmonsa/oci-workshop-labs.git
cd oci-workshop-labs/labs/01-elasticidad/terraform/elasticidad
cp terraform.tfvars.example terraform.tfvars   # completar
terraform init && terraform apply

Para generar los mismos paquetes que usa el botón, sin publicarlos: ./scripts/empaquetar-stacks.sh los deja en dist/, listos para subir a mano en Resource Manager.
